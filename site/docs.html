Introduction

CodeBase shows you what a software project is made of and how its parts fit together, in words you do not need a computer science degree to follow.

Who it is for

It is built for people who create apps with AI tools such as Cursor, Claude, ChatGPT or Copilot, including people who do not come from a programming background. The AI writes the code quickly; CodeBase helps you keep up with what it wrote, and helps you ask for the next change precisely.

What it does

  • Finds the architecture, not the folders. Every file gets the part it plays in the design (screen, API client, route, controller, business logic, model; or scenario, step definition, page object, driver, hook, test data), read from what the code does and what it is called. CodeBase then works out what kind of project it is and the order data moves through those parts.
  • Traces flows end to end. A screen is followed through the request it sends, the route that answers it, the controller, the business logic and the models. A test scenario is followed line by line to its step definitions, page objects, driver, hooks and data.
  • Puts journeys in order. Flows are grouped into journeys such as sign up, log in, request a ride, pay, and ordered the way people move through an app.
  • Keeps the whole history. Every commit in plain words, the design at any version compared with today, and automatic save points for folders without Git.
  • Checks the design. Scenario steps with no step definition, steps that skip page objects, files that depend on each other in a loop, code nothing uses.
  • Writes prompts. Describe a change or paste an error; CodeBase picks the files involved, adds the architecture and journeys, and fits it to your AI chat's size.

None of this needs an AI. CodeBase reads code without running it. An AI chat is optional, for naming journeys or describing files in your own project's words, and you paste its answer back yourself.

Everything stays on your computer

CodeBase is one program that runs a small private web page on your own machine (at http://127.0.0.1:4321). Your code is never uploaded. Prompts go nowhere until you copy and paste them yourself.

Quick start

Install CodeBase, open your first project, and make your first prompt. This takes about five minutes.

Install

Option A: download the program

If you received codebase.exe (Windows) or codebase (macOS, Linux), put it in any folder you like. There is nothing else to install.

TipOn Windows, the included CodeBase.bat starts the program with one double-click and keeps its window open if something goes wrong.

Option B: build it from source

You need Rust, which you can install from rustup.rs. Then, in the CodeBase folder:

terminal
cargo build --release

The first build downloads its libraries and takes a few minutes. The finished program is target/release/codebase (or codebase.exe on Windows). CodeBase.bat builds it for you automatically the first time if Rust is installed.

WindowsRust on Windows also needs the "Desktop development with C++" build tools. The Rust installer offers to set them up for you.

Open your first project

  1. Start CodeBase. Double-click CodeBase.bat, or run codebase in a terminal.
  2. Choose a folder. On the first run a folder picker opens. Choose the top folder of your project, the one that contains package.json, composer.json or similar. Next time CodeBase reopens your last project automatically.
  3. Let your browser open. CodeBase opens http://127.0.0.1:4321. Keep the black terminal window open while you work; closing it stops CodeBase.

You can also open a project directly from a terminal, by path or by GitHub link:

terminal
codebase "D:\projects\invoice-tracker"
codebase https://github.com/user/repo

Take a first look

  1. Overview says what the project is, what kind of design it has, the journeys people take through it, and anything that needs attention.
  2. Architecture draws the path data takes through the parts. Click a part to see its files and what it uses.
  3. Flows lists every journey in order. Pick a flow and press Play the flow to watch it move from the first screen or scenario line down to the data.
  4. Tree shows the project as a tree: project, parts, groups, files. Click a part to open it.
  5. History shows every version in plain words.

Teach it once

Automatic summaries are a start. For a much clearer map, give CodeBase plain descriptions of the project and its main folders:

  1. Open Memory and keep "The project and its main folders" selected. Press Build the prompt.
  2. Copy it into any AI chat (ChatGPT, Claude, Gemini, DeepSeek) and send it.
  3. Paste the answer back into step 3 and press Save descriptions.

Make your first prompt

  1. Open Ask AI and write what you want in your own words, for example "add a due date to invoices and show it in the list", or paste an error message.
  2. Pick a size that fits your chat, from 4k for small free chats to 32k for long-context models, and press Build context pack.
  3. Check the list. Every file shows why it was picked. Switch any file between full code, outline, summary or off.
  4. Copy the pack and paste it as the first message of a new chat. On a flow, Copy context for this flow does all of this in one click.

Architecture

Folders say where files are kept. Architecture says what each file does and how data moves between them. CodeBase shows the second.

Parts

Every file is given the part it plays in the design. CodeBase decides from three kinds of evidence, strongest first:

  1. What the code does. It defines web addresses, sends requests, starts a browser or device, finds screen elements, checks results, queries a database, or calls a payment or email service. A router that shows a component makes that component a screen, wherever it lives.
  2. What the file is called. article.service.ts is business logic and RideController.php is a controller, even inside a folder called routes/.
  3. Where it sits. Folder names fill the gaps: Pages/, StepDefinitions/, migrations/.

Kinds of project

KindThe path data takes
Test automation frameworkScenarios → test cases → step definitions → page objects → driver → app under test, with hooks, test data and settings beside it
Full-stack appScreens → UI components → state → API client → routes → guards → controllers → validation → business logic → external services → data access → models → database
Server-rendered web appRoutes → guards → controllers → validation → business logic → data access → models → database → templates
Backend APIStart-up → routes → guards → controllers → business logic → data access → models → database
Front-end or mobile appStart-up → screens → UI components → state → API client → server
Machine learning projectData loading → model → training → evaluation
Command-line toolStart-up → commands → business logic → external services → models

Only the parts your project has are drawn. A dashed arrow means the two parts are expected to connect but no import between them was found.

Design checks

CheckWhy it matters
Scenario steps with no step definitionThese lines fail with "step not found" when the test runs.
Step definitions that find screen elements themselvesThey skip the page objects, so a changed screen has to be fixed in several places.
Page objects that check resultsPass or fail belongs in the steps, so failures point at the right place.
A part that depends on a part later in the pathData flowing backwards makes the two hard to change separately.
Controllers that query the databaseOther code goes through business logic or data access; mixing both hides the rules.
Files that depend on each other in a loopA change in one ripples through all of them.
Step definitions no scenario uses, and code nothing reachesPossibly dead code, or loaded by the framework by name.

Flows and journeys

A flow is one thing happening from start to finish. A journey is the flows that belong together, like everything about logging in.

Kinds of flow

FlowStarts fromFollowed through
ScenarioA Gherkin scenario (SpecFlow, Reqnroll, Cucumber, behave)Each line to its step definition, then page objects, helpers, test data and driver. Background steps are included.
Maestro flowA Maestro YAML flowIts commands, the sub-flows it runs and the data files it reads.
TestA test function in an end-to-end or automation projectPage objects, data and driver.
RequestA web address the server answers, such as POST /api/ridesRoute, controller, validation, business logic, external services, data access, models.
ScreenA screen people visitIts components, state and API client, then across to the server route that answers each request it sends.

Journey order

Journeys are ordered the way people move through an app: set up, sign up, log in, profile, browse, create, plan, assign, track, pay, finish, log out. Inside a journey, screens and scenarios come first, then the requests that answer them: create, then read, then change, then delete.

Naming journeys with AI

Automatic journey names come from your code's words. For names a product person would use, open Flows, expand Name and order the journeys with your AI chat at the bottom, press Copy the prompt, paste it into any chat, paste its answer back and press Save journeys. Your names and order are saved in .codebase/memory.json and win from then on; Go back to automatic journeys undoes them.

What a flow cannot see

Flows follow imports and addresses in the code. Wiring that only happens when the program runs (dependency injection, routes built from strings, reflection) is invisible. A flow is per file, so a screen that imports one function from an API file is shown with every request that file sends.

The tree

The tree shows the project as an m-ary tree: the project, then its parts, then groups, then files. Every node has a fixed place, so nothing drifts.

3D

The parts stand in a row, left to right in the order data moves through them. A blue line with moving dots joins them along the data path. Each part's files sit on a ring below it. Drag to turn, scroll to zoom, click a part to open or close it.

2D

A flat tree read top to bottom in the same order, with file names always shown. Better for large projects and for reading names.

Show how parts connect

Draws a line from each part (or open file) to the parts it uses. Lines are summed, so a closed part shows one line however many of its files are involved.

History

Every version of the project in plain words, without any Git commands. CodeBase only reads; it never commits, pushes, pulls or switches versions.

The timeline

Each commit shows what kind of change it was (new thing, fix, clean-up, tests, docs, setup), which parts of the design it touched, and the files it added or removed. Tags appear as version markers. Filter by kind, by part, or by words in messages, files and names.

Compare the design then and now

Open a commit and press Compare the design then and now to see how many files each part had at that version, and which files have been added or removed since.

See one change

See change next to a file shows exactly which lines that commit added and removed.

Folders without Git

While CodeBase is open it records save points: which files were added, changed or removed, merging edits made within two minutes of each other. They are kept in .codebase/journal.json.

Projects opened by link

GitHub links are downloaded with their full history so every version shows. Projects downloaded by older builds, which kept only the newest commit, get their full history on the next update.

Ask AI

Ask AI builds a context pack: one block of text that gives your AI chat exactly the files it needs for a task, sized to fit the chat. CodeBase is the librarian; your chat is the expert.

1. Say what you want

Write the change in your own words, or paste an error message or stack trace exactly as you got it. CodeBase finds the project files an error names, even when the paths come from another computer, and notes the line numbers. Press Build context pack or Ctrl + Enter.

2. Pick a size

SizeUse it for
4kSmall free chats, or a very focused question
8kFree ChatGPT, Claude and Gemini (the default)
16kMost paid chats
32kLong-context models

Sizes are in tokens, the units AI chats count text in. CodeBase counts one token per four characters.

3. Check the list, then copy

Every chosen file shows why it was picked. Use its menu to change how it is included:

OptionWhat the AI gets
Full codeThe whole file. The AI may change it.
PartOnly the lines around an error. The AI may change it.
OutlineClass and function names only, so the AI knows the file exists.
SummaryOne line saying what the file does.
OffNothing.

Auto hands a file back to CodeBase. Press Copy context pack and paste it as the first message of a new chat. If the AI replies NEED FILES: …, add those files and copy again.

Copy context for this

Every file, folder and feature has a Copy context for this button. One click builds a pack around it and copies it; then type your request at the top of the chat. Files you pin (Shift + click on the map, or Pin to Ask AI) are always included in full.

How files are picked

Start files come from the error, from names you typed that a file defines, and from a keyword search over file names, definitions, summaries, your Memory notes and commit messages. CodeBase then adds what those files use, what uses them, their tests and files that Git says change together with them, and fills your size: full code first, outlines for neighbours, one-line summaries for the rest. Links come from reading the code, not running it, and the AI is told so.

Teaching CodeBase

Plain descriptions make the overview, feature stories and prompts much clearer. You can write them yourself or let any AI chat write them.

Three ways to describe

  • The project and its main folders. The best first step: one prompt covers the whole project.
  • Files without a description, most-used files first, in batches of 15, 30 or 60.
  • Files in one feature, from the Features page or the Memory list.

If the reply does not save

CodeBase expects a JSON object such as {"src/": "…"}. It also accepts lines in the form path: description. Paths that are not in the project are skipped and counted.

Outdated descriptions

When a described file changes, its details panel shows "This file changed after it was described". Press Still accurate to keep the text, or edit it. Memory can also build a prompt for every outdated description at once.

Hiding files

CodeBase skips noise automatically, and you can hide anything else.

Skipped automatically

Dependencies (node_modules, vendor), build output (dist, build, target), caches, virtual environments, lock files, minified files, source maps, Laravel's storage/framework and bootstrap/cache, and everything listed in the project's .gitignore files.

Your own rules

Clean up suggests generated, minified and very large files. You can also add patterns in .gitignore syntax:

PatternHides
public/assets/That folder and everything in it
*.generated.tsEvery file ending in .generated.ts
/notes.mdOnly notes.md at the top of the project

Command line

Everything the codebase program accepts.

usage
codebase [folder | git-url] [--pick] [--port 4321] [--host 127.0.0.1] [--no-open]
OptionEffect
folderOpen a local folder. Relative paths are fine.
git-urlClone a repository into ~/.codebase/repos (or update it if already there), then open it. Needs Git.
(nothing)Reopen the most recent project; on first run, show a folder picker (Windows) or use the current folder.
--pickAlways show the folder picker (Windows).
--portFirst port to try. If it is busy, the next free one up to 20 higher is used.
--hostNetwork address to listen on. Use 0.0.0.0 to open CodeBase from another device on your network.
--no-openDo not open the browser automatically.
--version, --helpPrint the version or a short help text.
SecurityWith --host 0.0.0.0, anyone on the same network can read your code through CodeBase. Use it only on networks you trust.

Local HTTP interface

The app talks to the program over a small local API. It is documented here for people who want to script it.

RequestReturns
GET /api/graphEvery file and its part, links, the architecture (arch), design checks, flows and journeys.
GET /api/timelineCommits in plain words, uncommitted edits and save points.
GET /api/at?rev=…The design at a commit or tag, compared with today.
GET /api/diff?rev=…&path=…What one commit changed in one file.
POST /api/journeysSaves journey names and order: {"journeys": [{"name", "about", "flows": [ids]}]}, or null to go back to automatic.
POST /api/contextBuilds a context pack: task, budget, pins, seeds, modes.
GET /api/file?path=…One file: summary, description, links, definitions and content.
GET /api/poll?since=NChanges since version N.
POST /api/notesSaves descriptions: {"notes": {"path": "text"}}.
POST /api/openOpens a project: {"target": "path or link"}.

Troubleshooting and FAQ

Answers to the questions that come up most.

The browser still shows an old version

Only one CodeBase window should be running. Close every CodeBase terminal window, start it again, and reload the page. Because the whole interface is built into the program, replacing the program replaces the interface.

Windows blocks the program

Right-click the file, choose Properties, tick Unblock and press OK. SmartScreen may also ask you to confirm the first time you run it.

A file shows no links

CodeBase finds links by reading import statements, Laravel namespaces, view names, types used from other files, and data files named in strings. Links made at run time, through service containers, string-based routes or dynamic imports, cannot be seen without running the code.

The tree feels slow

Press Parts only, switch to 2D, and hide large folders you do not need in Clean up. Above roughly 3,000 open files the 3D view gets heavy on older computers.

A file is in the wrong part

CodeBase goes by what the code does, then the file name, then the folder. A file that does two jobs is put where its strongest evidence points. Describe it in Memory so the next person, and every context pack, knows what it really does.

No flows were found

Flows start from screens a router shows, web addresses the server answers, and test scenarios. A library, or an app whose routes are built at run time, may have few or none; Architecture and the tree still show its design.

Does CodeBase send my code to an AI?

No. It never contacts any AI service. It only builds text that you choose to copy into an AI chat.

The port is already in use

CodeBase tries ports 4321 to 4340 and uses the first free one, then prints the address in its window. You can run several projects at once this way.
